## RCA

### P-01：初期値の物理量の取り違え

- なぜ 1：侵入の速さを `v² = v_inf² + 2·2/R` で求め、μ に q を渡した。
- なぜ 2：初期値の式は手で導いた。テストが見ていたのは帰結（入れ替わりが起きる、L4 にとどまる）だけで、作った状態が意図した値になっているかは見ていなかった。
- なぜ 3：帰結は、パラメーターが少しずれても変わらない。そのため帰結のテストでは取り違えを検出できない（Codex の指摘のとおり）。
- なぜ 4：プリセットの設計の手順に、「説明に書いた物理量を、作った状態から測る」という段がなかった。
- **根本原因**：プリセットの設計で、文書に書いた物理量（エネルギー、質量の比、軌道の要素）を、作った状態から測って確かめる手順がない。
- **再発防止策**：
  - README の「開発の進め方」に手順として書いた。
  - テスト `preset_stated_quantities_hold_in_initial_states` を足した。Kepler-16・古在・シトニコフ・トロヤ群・侵入の、説明に書いた量を初期状態から測る。Kepler-16 の離心率と古在の外側の半径をわざと変えると失敗することを確かめた。

### P-02：同じであることの主張と、テストの条件の食い違い

- なぜ 1：テストの「画面と同じ条件」が、画面と許容誤差や刻み幅で違っていた。
- なぜ 2：テストは画面の既定を、手で写した定数（1e-3、1e-10）で組み立てていた。
- なぜ 3：画面の既定は TypeScript と HTML にあり、テストと共有していなかった。
- なぜ 4：主張を書くとき、それが含む条件（丸め、積分法、許容誤差、最初の刻み幅）を列挙していなかった。そのため直すたびに、残りの条件を見落とした。
- **根本原因**：「〜と同じ」という主張に対して、条件を列挙し、値の出どころを 1 か所にする手順がない。
- **再発防止策**：
  - 最初の刻み幅は `scenarios::preset_dt` の 1 か所にまとめた（82464cc）。
  - 積分法と許容誤差の既定は HTML にあり、Rust から読めない。そこで、ページの既定がテストの値と一致することを e2e で確かめるようにした（この振り返りの PR）。
  - 手順は README の「開発の進め方」と、作業の決まり（手元）に書いた。「すべて」「両方」の決まりは、PR だけでなく計画書とページにも当てはめる。
